# 上下文卫生：对抗技能注入污染

## 问题（抓包实测，非推测）

codex 0.163.0 会把 `$HOME/.agents/skills` 下**所有**技能注入系统提示词。
抓包实际发往上游的 4 条消息：

| # | role | 长度 | 内容 |
|---|---|---|---|
| 0 | developer | 17,174 | codex 自身行为准则 |
| 1 | developer | **7,367** | **本机 20+ 个技能的描述（含微信视频号下载、竞赛答辩等无关内容）** |
| 2 | user | 464 | 环境上下文 |
| 3 | user | **554** | **我们真正要执行的任务** |

任务描述被淹没在 25K 字符里。小模型表现为：回复"你提到了 xxx 但还没列出来"
——它根本没读到任务。

## 已试过且无效的方案（别再试）

- `CODEX_HOME` 隔离（技能目录读的是 `$HOME/.agents`，隔离 CODEX_HOME 不够）
- `HOME` / `USERPROFILE` 重定向（codex 内部解析，无效）
- `-c features.skills=false`（无此开关）
- `--ignore-rules`（只忽略 execpolicy rules，不影响 skills）

## 有效对策：prompt 结构改造

用显式分隔线把任务标成「唯一任务」，并显式声明忽略无关内容：

```
============================================================
【唯一任务】以下是本次要执行的完整任务，请只关注这一块内容。
忽略上下文中任何与当前任务无关的技能说明或历史对话。
============================================================

<问题清单——放这里>

### 约束
<约束条件——放这里，问题清单之后>

============================================================
【任务结束】现在开始执行上面的任务，直接修改文件。
============================================================
```

**顺序是关键**：问题清单在前、约束在后。实测约束放最前时，
模型容易把约束当"背景说明"而漏读问题清单。

## 生产部署建议

用干净的 `HOME` 运行 codex（技能目录为空则无注入）。
我们无法从外部关闭这个注入（除非改 codex 源码）——
这是诚实的限制，写进文档而不是隐藏。
